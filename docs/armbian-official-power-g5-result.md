# G5 供电读取结果（2026-10-29）

F8AG5的45份白名单日志已保存至local/hardware/armbian-official-g5-20261029-01，test-result.json记录逐文件哈希。镜像preflight已标实际读取通过并保留before-hardware副本，仍不标充电控制通过。

## 为什么日志盘较慢

试验RAM overlay中的报告timer设为OnActiveSec=210s，在系统启动试验目标后开始计时；不是从上电瞬间计时。早期读取在启动44.187秒，晚期读取在253.887秒。日志整理、关闭FAT并导出只读USB镜像还需少量时间，因此约4–5分钟。该间隔是G3以来为触摸90秒窗口及完整日志预留的设计，G5复用并用于两次供电快照，不是I2C重试造成。

下一版可缩短测试和timer等待以减少周转时间；必须在卸载FAT、完成快照之后才挂出USB盘，不在电脑挂载同一个FAT镜像时继续写入。当前G5镜像不改写；勿把源码基础timer的110s误认为已打包G5内的210s。

## 实测证据

- I2C6物理路径fec80000和m3引脚验证通过；BQ 0x6a和CW 0x62早晚均complete=true，无寄存器值写入。
- BQ PN=3；两份所读原始寄存器完全一致。当前设定输入限流3A、充电电流设定2.944A、VREG4.4V、终止电流64mA；CHG使能、OTG禁用、watchdog禁用、安全timer启用。这是芯片当前配置，不等于实际输入/充电电流，不证明电脑USB可供3A。
- 旧原系统sysfs曾报告充电电流上限2.496A，与本次原始设定2.944A不同，不能据此直接认定旧策略已复原或默认配置可接受。当前4.4V寄存器为新证据，但不替代旧驱动完整策略审查。
- BQ ADC对应电压4.244V，两次原始ADC相同，转换未启动，时效未确认，不能拿来判断实际充电趋势。状态为charging_status=2/PG=true，但VBUS类型代码0；不将此组合认定为电源类型/充电验收。
- CW原始模式normal、电量100%；原厂64字节曲线逐字节匹配，SHA f75d42e84a2e43535a55b83dba6f9d62e0aca7458c416e60a282f9412bff37f3。单次电压按参考公式早期4238mV、晚期4225mV；未平均、未验证校准，也不能仅由此断言充放电电流方向。
- GPU硬件像素读回继续通过，触摸设备存在，日志快照无panic/Oops。
