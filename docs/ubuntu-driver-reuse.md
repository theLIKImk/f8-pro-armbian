# 原 Ubuntu 驱动与硬件资产的复用

2026-10-29。迁移优先复用原 Ubuntu 已验证的驱动源码、固件和板级参数。是否能直接使用取决于内核接口，不取决于系统叫 Ubuntu 还是 Armbian。

现有原厂镜像为 update-UBUNTU20.04.img；归档清单 vendor/ubuntu-5.10.160/manifest.json 保存来源与哈希。已检查的本地原厂资产包括 5.10.160 Image、DTB、U-Boot、固件、GPU 库和采集结果，没有在这些目录找到对应完整内核/板级驱动源码。这个结论限于已检查资料，不代表厂商没有源码。当前完整可编译树是固定的目标 6.1.172 源码。

| 原厂资产 | 复用方式 | 当前限制 |
| --- | --- | --- |
| Wi-Fi/蓝牙及触摸固件 | 保存原始字节、哈希，按新驱动所需路径或 board profile 使用 | 固件名、上传协议、NVRAM/板型须对应 |
| DTB、面板初始化、背光、电池曲线 | 提取原数值，迁移供电/GPIO/时钟/graph 与板级配置 | 新驱动不一定读取旧属性；参数相同不证明功能通过 |
| 有对应源码的内核驱动 | 保留设备逻辑，适配目标内核 API 后重编译 | 需匹配实际硬件和原厂定制行为 |
| 5.10.160 的预编译 .ko 或内建驱动 | 作原厂行为依据；有源码时重新编译 | 不直接装入 6.1.172；从 Image 提取数据不等于恢复完整 C 源码 |
| 原 Mali/摄像头用户态库与服务 | 先核对内核接口、图形/媒体栈和系统依赖 | 不能直接假定与新内核、Mesa/Wayland 兼容 |

已有迁移并非重写所有外设：PMIC、存储、时钟和多种外设沿用目标内核现有实现；原厂设备树与参数用于本板配置。触摸因原厂 r8/shuping 与目标通用驱动存在差异，才需要板级 profile；电池/充电因为目标忽略部分原属性，仍需补行为而不是只复制 DTB。

## 本轮直接沿用的触摸行为

原厂 r8 startup 从所选 board config 的 +16 取算法指针，调用 gsl_DataInit；目标有同名函数及 512-word 配置解析源码。已经核对调用路径及接口形状，但没有证明原厂与目标算法二进制实现相同。

反汇编确认原厂 reset 三段循环为 20/10/10 次，startup 为 10 次，均调用 __const_udelay；对应常量 0x418958 与固定源码的 1000×0x10c7 宏一致。因此推导标称等待分别为 20/10/10ms 和 10ms，而目标通用代码为 5/5/5ms 和 5ms。该结论是静态推导，不是实际时间测量。报告 analysis/armbian/touch-static/startup-contract.json。

专用候选 profile 已沿用这组标称等待，通用 profile 保持原值。没有继续猜测一个全新的复位协议；寄存器顺序继续依据原厂路径比较。更新后应检查 candidate-r8-shuping/compile-check.json 与 transport-check.json 的同版源码哈希。延时测试只核对调用参数，硬件时钟、GPIO 波形和实际启动仍未验证。
