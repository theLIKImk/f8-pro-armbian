# G5 供电只读诊断短测（2026-10-29）

G5以触摸/GPU已通过真机测试的G4为基线。它是准备充电适配的诊断镜像，尚未提供可验收的充电控制。无需重新上传官方Armbian根文件系统。

## 变更与检查

- I2C6从m0切到原厂m3，GPIO4_B0/B1，功能9；新增引脚组的电气配置逐属性与原厂一致。除model标识和这处引脚组/引用，设备树完全相同。
- BQ25890和CW2015节点继续disabled。通过官方内核内置i2c-dev访问原厂固定地址0x6a、0x62，不扫描其他地址。启动约45秒和报告阶段各读取一次配置；实际时刻记录在JSON中。
- 采集前核验I2C6物理控制器路径、实际引脚组、两个节点禁用且未绑定驱动，I2C_SLAVE检查地址未被内核驱动占用。诊断不使用force ioctl。
- I2C读事务包含一个寄存器地址字节，随后重复START读数据；不发送配置值写入。无芯片复位、ADC转换启动、曲线写入、限流改写、PD/OTG使能。BQ REG0C故障锁存寄存器跳过，避免读取改变锁存记录。
- 读取BQ配置/状态，识别芯片PN后再应用BQ25890换算；不同PN保留原始值而不套用缩放。CW读取原始电量/电压/模式和64字节曲线，对照原厂曲线。电压单次采样不代表平均电压或充电终止设定；旧ADC样本时效未确认。
- 模块、固件、GPU、触摸、内核、根镜像保持G4内容；RAM overlay只新增采集脚本与日志调用、更新版本/卷标。

协议测试验证7段允许区域均只发送单字节寄存器指针、跳过故障寄存器、拒绝未列出读操作，并核对500mA/2.496A/4.4V/64mA解析样例及不明型号不解码。ARM64官方根中的无硬件负向测试明确失败并保存JSON。shell语法、FAT/CPIO受限差异、FIT四负载哈希、64MiB分区及内存无重叠检查通过。硬件读取仍待用户启动实测。

## 文件与刷入

镜像：outputs/armbian/official-f8-power-g5/BOOT_ONLY_ARMBIAN_26.8.1_POWER_G5_DIAGNOSTIC.img

大小49473972字节。SHA256：

`5426928173b5c79b3a6930416f3b0c86aefdb17acd7824391e20d072809f1697`

预检同目录preflight.json；构建tools/build-f8-power-g5.py；采集armbian/official-graphics/power-readonly.py。

1. 如正在原系统充电，先补足电量再开始短测。当前是否已回原BOOT尚未确认。
2. 沿用RKDevTool下载镜像流程，只刷boot，起始LBA **0x00008000**，原分区0x00020000扇区。不擦除或刷其他分区。
3. 本轮**连接电脑USB**，无需切换到用户提供的5V3A/9V2.22A/12V1.67A充电器。铭牌不能确认快充协议；G5不进行高压协商或充电器插拔验证。
4. GPU/触摸窗口行为与G4相同，等4–5分钟出现 **F8AG5** 日志盘。
5. 在原日志之外重点保存POWER0.JSON、POWER1.JSON、POWER0.TXT、POWERLOG.TXT、POWERBUS.TXT；complete=true只表示读取完整，不表示已经充电成功。

下一步对比早晚寄存器与原厂参数，核实芯片型号、有效限流/限压、CW曲线及模式。若仍无法解释旧驱动策略，需要在原BOOT下继续只读核对；不要仅凭本次寄存器快照就认定4.2V/4.4V二义性已消除。之后实现带明确约束的5V充电控制、匹配官方ABI的驱动，再验证供电插拔/温度/电量和USB-C角色；高压快充排在这些检查之后。

回退仍用outputs/armbian/firstboot-diagnostic/CURRENT-BOOT-ROLLBACK-64MiB.img，只刷boot。原系统下按原方式充电。
